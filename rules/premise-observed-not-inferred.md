# Premise Observed, Not Inferred

**A load-bearing premise must be observed, not inferred.**

Fires before building on anything whose falsity would restructure the work: a
trust boundary, a dependency's readiness, a storage model, what the consumer
sees, the plan's architecture. Ask whether you observed it or inferred it from a
document, a green signal, a sibling or a habit. Then run the cheapest direct
observation first: probe, open the artifact, ask the owner. For runtime behaviour,
reading the source is still inference; executing it is the observation. Read the
playbook,
[`~/.claude/rule-playbooks/premise-observed-not-inferred.md`](~/.claude/rule-playbooks/premise-observed-not-inferred.md),
for the economics, the new-surface procedure and the surfaces it governs. For a
diagnosis rather than a build, see
[`diagnose-from-observation-not-prior.md`](diagnose-from-observation-not-prior.md).

## Red Flags

- "should be", "presumably", "the plan says", "it'll be ready by then" attached to something load-bearing.
- Confidence that comes from a document or a green higher-layer signal rather than the substrate.
- A verification list that exercises everything around the premise but never the premise.
- You cannot name the single observation that would falsify it.
